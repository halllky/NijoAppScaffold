# 定数（Constants）

`Constants` セクションには、C#とJavaScript/TypeScriptで常に値が同期される定数を定義します。

## 概要

`Constants` セクションに定数を定義することで、以下のメリットがあります：

- **型安全性**: 定数値をハードコードする代わりに、型安全な定数として定義できます
- **同期性**: C#とJavaScript/TypeScript間で定数値が自動的に同期されます
- **保守性**: 定数値の変更時に、一箇所の変更で全体に反映されます
- **階層構造**: ネストされた定数グループにより、論理的な構造を持った定数定義が可能です

## サポートされる定数の種類

### 基本型

| 型         | 説明               | C#での型  | TypeScriptでの型 |
| ---------- | ------------------ | --------- | ---------------- |
| `string`   | 文字列定数         | `string`  | `string`         |
| `int`      | 整数定数           | `int`     | `number`         |
| `decimal`  | 小数定数           | `decimal` | `number`         |
| `template` | テンプレート文字列 | 関数      | 関数             |

### テンプレート文字列

`template` 型を使用すると、引数を受け取って文字列を返す関数が生成されます。
メッセージの文言や画面の URL のように、値を埋め込んで使う文字列に使います。

#### 引数の書き方

引数は `{名前}` か `{名前:型}` の形で書きます。名前がそのまま関数の引数名になります。

| 型                 | C#での型 | TypeScriptでの型 |
| ------------------ | -------- | ---------------- |
| `string`（省略時） | `string` | `string`         |
| `int`              | `int`    | `number`         |

- 同じ名前の引数を複数回書くと、1つの引数の値が各箇所に埋め込まれます。
- `int` の引数は、C# と TypeScript で同じ文字列になるように、カルチャに依存しない形式で文字列にしてから埋め込まれます。
- 波括弧そのものを文字として使う場合は、`{{` `}}` と2つ重ねて書きます。
- 次のものは、nijo のスキーマ定義の検証でエラーになります。
  - `{0}` のような番号の引数や、重ねていない波括弧。
  - 表に無い型。
  - 同じ名前の引数に、異なる型を指定したもの。

#### テンプレートの種類

引数の値をそのまま埋め込むと困る場合があります。
たとえば URL に `/` や `?` を含む値をそのまま埋め込むと、別の URL になってしまいます。
JSON の文字列に `"` を含む値をそのまま埋め込むと、JSON が壊れます。

そのため、テンプレート文字列には種類（`TemplateKind` 属性）を指定します。
引数の値は、種類ごとの変換を通してから埋め込まれるので、呼び出し側でエンコードを書く必要はありません。
種類の名前（`URL`、`JSON`、`文言` など）と変換の中身は、アプリごとに決めます。nijo が用意している種類はありません。

- グループに指定すると、その中のテンプレート文字列すべての既定値になります。
- 入れ子のグループやテンプレート文字列の定数に指定すると、外側のグループの指定を上書きします。最も内側の指定が使われます。
- 自身にも外側のグループにも指定が無いテンプレート文字列は、スキーマ定義の検証でエラーになります。

画面に出すメッセージのように変換が要らない場合も、種類の指定は省略できません。
値をそのまま返す変換を持つ種類（`文言` など）を定義して指定してください。
どの値が変換されずに埋め込まれるのかを、定義から読み取れるようにするためです。

#### 変換の中身を書く

変換の中身は自動生成されないので、開発者が次の2つのファイルを作って書きます。
nijo が生成するのは、nijo.xml に指定された種類ごとの変換の宣言だけです。テンプレート文字列がまだ無いグループに指定した種類も宣言されます。
C# は `ConstantTemplateKind` クラスの partial メソッド宣言、TypeScript は `ConstantTemplateKind` の型の宣言として生成されます。
そのため、変換が書かれていない種類があると、C# も TypeScript もコンパイルエラーになります。

| 言語       | ファイル                                                    | 書き方                                                     |
| ---------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| C#         | 自動生成されるプロジェクト（Core.AutoGenerated）直下の `ConstantTemplateKind.cs` | 生成されるコードと同じ名前空間の、`ConstantTemplateKind` クラスの partial メソッド |
| TypeScript | React プロジェクトの `src/ConstantTemplateKind.ts`          | export する `ConstantTemplateKind` オブジェクトのプロパティ |

C# のファイルを Core.AutoGenerated に置くのは、自動生成されるコードから呼ぶために、同じプロジェクトに置く必要があるためです。
自動生成されるのはこのプロジェクトの `__AutoGenerated` フォルダの中だけなので、その外に置いたファイルは上書きされません。

サーバーと画面で同じ文字列を組み立てられるように、C# と TypeScript の変換は同じ結果になるようにしてください。

#### 定義例

```xml
<!-- 画面の URL。サーバーで組み立てて通知のリンク先にし、画面のルーティングにも使う。 -->
<画面のURL TemplateKind="URL">
  <売上詳細 ConstantType="template" ConstantValue="/uriage/edit/{売上SEQ:int}" />
</画面のURL>

<!-- 外部システムとの連携に使う文字列。 -->
<外部連携 TemplateKind="文言">
  <認証ヘッダー ConstantType="template" ConstantValue="Bearer {トークン}" />
  <!-- JSON の値に埋め込むので、グループの指定を上書きする。 -->
  <連携データ ConstantType="template" ConstantValue="{{&quot;name&quot;: &quot;{名前}&quot;}}" TemplateKind="JSON" />
</外部連携>
```

変換の中身は次のように書きます。

**C#（Core.AutoGenerated/ConstantTemplateKind.cs）:**
```csharp
using System.Text.Encodings.Web;
using System.Text.Json;

namespace MyApp;

public static partial class ConstantTemplateKind {
    public static partial string URL(string value) => Uri.EscapeDataString(value);
    public static partial string 文言(string value) => value;
    public static partial string JSON(string value) => JsonEncodedText.Encode(value, JavaScriptEncoder.UnsafeRelaxedJsonEscaping).ToString();
}
```

**TypeScript（src/ConstantTemplateKind.ts）:**
```typescript
export const ConstantTemplateKind = {
  // encodeURIComponent は !'()* をエンコードしないので、C# の Uri.EscapeDataString に合わせる
  URL: (value: string): string => encodeURIComponent(value)
    .replace(/[!'()*]/g, c => `%${c.charCodeAt(0).toString(16).toUpperCase()}`),
  文言: (value: string): string => value,
  JSON: (value: string): string => JSON.stringify(value).slice(1, -1),
}
```

#### 生成されるコード

C# では、引数を埋め込んだ文字列を返す静的メソッドが生成されます。

```csharp
public static class 画面のURL {
    public static string 売上詳細(int 売上SEQ) => $"/uriage/edit/{ConstantTemplateKind.URL(売上SEQ.ToString(System.Globalization.CultureInfo.InvariantCulture))}";
}
```

TypeScript では、`format` と `pattern` の2つの関数を持つオブジェクトが生成されます。

- `format`: 引数を変換してから埋め込んだ文字列を返します。引数の型は表のとおりです。
- `pattern`: 引数の位置に、渡された文字列を変換せずにそのまま置きます。引数はすべて文字列で受け取ります。
  React Router のルート定義（`/uriage/edit/:id`）のように、引数の位置に値以外のものを置きたい場合に使います。`format` では `:` もエンコードされてしまうためです。
  C# には、これに当たるものは生成されません。

```typescript
画面のURL.売上詳細.format({ 売上SEQ: 123 })      // "/uriage/edit/123"
画面のURL.売上詳細.pattern({ 売上SEQ: ':id' })   // "/uriage/edit/:id"
```

## XML定義例

### 基本的な定数定義

```xml
<MyConstants DisplayName="アプリケーション定数">
  <!-- クライアント側のトップページの表示に利用。 -->
  <AppName ConstantType="string" ConstantValue="MyApplication" DisplayName="アプリケーション名" />
  <!-- csprojファイルのバージョン番号と合わせること。 -->
  <Version ConstantType="string" ConstantValue="1.0.0" DisplayName="バージョン" />
  <MaxRetryCount ConstantType="int" ConstantValue="3" DisplayName="最大リトライ回数" />
  <TimeoutSeconds ConstantType="decimal" ConstantValue="30.5" DisplayName="タイムアウト秒数" />
</MyConstants>
```

### ネストされた定数定義

```xml
<!-- アプリケーション設定の定数定義 -->
<MyConstants DisplayName="アプリケーション設定">
  <Database ConstantType="child" DisplayName="データベース設定">
    <ConnectionTimeout ConstantType="int" ConstantValue="30" DisplayName="接続タイムアウト" />
    <CommandTimeout ConstantType="int" ConstantValue="60" DisplayName="コマンドタイムアウト" />
  </Database>

  <Messages ConstantType="child" DisplayName="メッセージ" TemplateKind="文言">
    <Success ConstantType="string" ConstantValue="正常に処理されました" DisplayName="成功メッセージ" />
    <!-- コロンの後ろには開発者向けの情報ではなくアプリケーションのユーザーに向けた文字にすること。 -->
    <Error ConstantType="template" ConstantValue="エラーが発生しました: {詳細}" DisplayName="エラーメッセージ" />
  </Messages>
