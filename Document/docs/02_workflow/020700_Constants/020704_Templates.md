# テンプレート文字列（Templates）

`Templates` セクションには、値を埋め込んで使う文字列を定義します。
画面の URL やメッセージの文言のように、サーバーと画面の両方で同じ文字列を組み立てたいものに使います。
C# と TypeScript に、引数を受け取って文字列を返す関数が生成されます。

## 定義の書き方

```xml
<Templates>
  <!-- 画面の URL -->
  <画面のURL TemplateKind="URL">
    <売上一覧 Template="/uriage" />
    <売上詳細 Template="/uriage/edit/{売上SEQ:int}" />
  </画面のURL>

  <!-- 外部システムとの連携に使う文字列 -->
  <外部連携 TemplateKind="文言">
    <認証ヘッダー Template="Bearer {トークン}" />
    <!-- JSON の値に埋め込むので、グループの指定を上書きする -->
    <連携データ Template="{{&quot;name&quot;: &quot;{名前}&quot;}}" TemplateKind="JSON" />
  </外部連携>
</Templates>
```

`連携データ` は、XML のエスケープを戻すと `{{"name": "{名前}"}}` で、`{"name": "（名前の値）"}` という文字列を組み立てます。

- セクション直下の要素はグループです。
- グループの中の要素は、子要素を持てばグループ、持たなければテンプレート文字列になります。
- テンプレート文字列は `Template` 属性に書きます。グループに `Template` 属性を書くとエラーになります。
- 要素の名前は、そのまま C# と TypeScript の名前になります。C# の識別子として使える名前にしてください。

### 引数

引数は `{名前}` か `{名前:型}` の形で書きます。名前がそのまま関数の引数名になります。

型は、データ構造のメンバーの `Type` 属性と同じ型名で指定します（`word`、`int`、`decimal`、`date`、静的区分や値オブジェクトの名前など）。省略すると `word` になります。
C# と TypeScript での型も、データ構造のメンバーと同じものになります。
たとえば整数は、C# では `int`、TypeScript では画面のデータと同じく文字列です。
バイト配列は使えません。

- 同じ名前の引数を複数回書くと、1つの引数の値が各箇所に埋め込まれます。
- 引数の無いテンプレート文字列も、引数の無い関数として生成されます。
- 引数の型は null を許容しない型で生成されるので、null を渡すとコンパイル時に型エラーになります。値が無いときにどうするかは、呼び出す側で決めてください。
- 波括弧そのものを文字として使う場合は、`{{` `}}` と2つ重ねて書きます。
- 次のものは、nijo のスキーマ定義の検証でエラーになります。
  - `{0}` のような番号の引数や、重ねていない波括弧
  - 存在しない型名や、バイト配列
  - 同じ名前の引数に、異なる型を指定したもの

### テンプレートの種類

引数の値をそのまま埋め込むと困る場合があります。
たとえば URL に `/` や `?` を含む値をそのまま埋め込むと、別の URL になってしまいます。
JSON の文字列に `"` を含む値をそのまま埋め込むと、JSON が壊れます。

そのため、テンプレート文字列には種類（`TemplateKind` 属性）を指定します。
引数の値は、種類ごとの変換で文字列にしてから埋め込まれるので、呼び出し側でエンコードを書く必要はありません。

変換は、種類と引数の型の組み合わせごとに書きます。
同じ整数でも、URL には桁区切りを付けずに、画面に出す文言には3桁ごとに区切って埋め込みたい、というように、値を文字列にする書式は種類によって変わるためです。

- 種類の名前（`URL`、`JSON`、`文言` など）と変換の中身は、アプリごとに決めます。nijo が用意している種類はありません。
- 種類の名前は、変換を書く関数の名前になります。C# の識別子として使える名前にしてください。
- グループに指定すると、その中のテンプレート文字列すべての既定値になります。
- 入れ子のグループやテンプレート文字列に指定すると、外側のグループの指定を上書きします。最も内側の指定が使われます。
- 自身にも外側のグループにも指定が無いテンプレート文字列は、スキーマ定義の検証でエラーになります。

画面に出すメッセージのように変換が要らない場合も、種類の指定は省略できません。
値をそのまま返す変換を持つ種類（`文言` など）を定義して指定してください。
どの値が変換されずに埋め込まれるのかを、定義から読み取れるようにするためです。

## 生成されるもの

| 言語       | 生成先                                                   | 生成されるもの                                                                 |
| ---------- | -------------------------------------------------------- | ------------------------------------------------------------------------------ |
| C#         | 自動生成されるプロジェクト（Core.AutoGenerated）の `Templates.cs` | 種類ごとの変換を宣言した `ITemplateKind` インターフェースと、テンプレート文字列を入れた `Templates<TKind>` クラス |
| TypeScript | React プロジェクトの `src/__autoGenerated/templates.ts`   | 種類ごとの変換の型 `TemplateKind`、変換を受け取ってテンプレート文字列を返す `createTemplates` 関数、`TemplatePattern` |

種類ごとの変換の中身は生成されません。
自動生成されたコードがアプリ側のコードを参照しないように、変換はアプリ側から渡す形になっています。
変換が書かれていない組み合わせがあると、C# も TypeScript もコンパイルエラーになります。

変換が宣言されるのは、次の組み合わせだけです。
静的区分を何十個定義していても、テンプレート文字列の引数に使っていなければ、変換を書く必要はありません。

- 種類ごとに、その種類のテンプレート文字列で実際に使われている引数の型
- 種類ごとに、文字列型（`string`）。引数の無いテンプレート文字列しか持たない種類でも、変換を書いておけるようにするため

C# の型が同じ nijo の型（整数と連番など）は、同じ変換を使います。
C# では引数の型ごとのオーバーロード、TypeScript では C# の型名をキーにしたオブジェクトとして宣言されます。

## アプリ側で書くもの

C# と TypeScript のそれぞれで、種類ごとの変換を書き、それを自動生成されたテンプレート文字列に渡します。

### C#

`ITemplateKind` を実装したクラスに、種類と同じ名前の静的メソッドとして、引数の型ごとに変換を書きます。

```csharp
using System.Globalization;

namespace MyApp;

/// <summary>テンプレート文字列の種類ごとの、引数の値を埋め込む文字列にする変換。</summary>
public sealed class TemplateKind : ITemplateKind {
    public static string URL(string value) => Uri.EscapeDataString(value);
    public static string URL(int value) => URL(value.ToString(CultureInfo.InvariantCulture));
    public static string 文言(string value) => value;
    public static string 文言(int value) => value.ToString("#,0", CultureInfo.InvariantCulture);
}
```

テンプレート文字列を使うプロジェクトの csproj で、`Templates<TemplateKind>` を using static します。
グループのクラスを、型引数を書かずに直接参照できるようになります。

```xml
<ItemGroup>
  <Using Include="MyApp.Templates&lt;MyApp.TemplateKind&gt;" Static="true" />
</ItemGroup>
```

自動生成されるプロジェクト（Core.AutoGenerated）には書きません。`TemplateKind` を参照できないためです。
同じ理由で、全プロジェクトに効く Directory.Build.props にも書けません。

インターフェースの静的抽象メンバー（C# 11 以降）を使っています。

### TypeScript

`createTemplates` に種類ごとの変換を渡して呼び、その結果を export します。

```typescript
// src/テンプレート.ts
import { createTemplates } from "./__autoGenerated/templates"

export const テンプレート = createTemplates({
  URL: {
    string: (value: string) => encodeUrlComponent(value),
    int: (value: string) => encodeUrlComponent(value),
  },
  文言: {
    string: (value: string) => value,
    int: (value: string) => new Intl.NumberFormat("ja-JP").format(Number(value)),
  },
})

// encodeURIComponent は !'()* をエンコードしないので、C# の Uri.EscapeDataString に合わせる
function encodeUrlComponent(value: string): string {
  return encodeURIComponent(value)
    .replace(/[!'()*]/g, c => `%${c.charCodeAt(0).toString(16).toUpperCase()}`)
}
```

宣言されていない変換を余分に渡しても、エラーにはなりません。
テンプレート文字列を消したことで使われなくなった型の変換も、消さずに残しておけます（C# の余分なオーバーロードと同じです）。
ただし、宣言されていない変換は引数の型を推論できないので、変換の引数には型を書いておいてください。

使う側では、使うグループを取り出してから呼びます。

```typescript
import { テンプレート } from "../テンプレート"

const { 画面のURL } = テンプレート
```

グループを `src/テンプレート.ts` でまとめて export しないのは、グループを nijo.xml から消したときに、使っていた画面のファイルだけを消せば済むようにするためです。

### C# と TypeScript の変換をそろえる

サーバーで組み立てた URL を画面のルーティングで受けるときのように、両方の結果が一致しないと不具合になる場合があります。
C# と TypeScript の変換は、同じ入力に対して同じ文字列を返すようにしてください。
上の例でも、URL の変換は `!'()*` の扱いを C# に合わせています。

特に静的区分は、C# では enum、TypeScript では表示名の文字列で表されます。
C# 側の変換で、enum の値を表示名（`[Display(Name = "…")]`）に直してから埋め込むようにしてください。
nijo はこの一致を検査しないので、必要に応じてアプリ側のテストで確かめてください。

## 使い方

C# と TypeScript のどちらも、グループをたどって関数を呼びます。
TypeScript の引数は、名前つきのオブジェクトで渡します。

```csharp
画面のURL.売上一覧()                 // "/uriage"
画面のURL.売上詳細(123)              // "/uriage/edit/123"
```

```typescript
画面のURL.売上一覧()                    // "/uriage"
画面のURL.売上詳細({ 売上SEQ: "123" })  // "/uriage/edit/123"
```

### ルート定義などのパターン文字列を作る（TypeScript のみ）

React Router のルート定義（`/uriage/edit/:id`）では、引数の位置に値ではなく `:id` のような記号を置きます。
`画面のURL.売上詳細` では `:` もエンコードされてしまうため、この用途には自動生成された `TemplatePattern` を使います。

```typescript
import { TemplatePattern } from "./__autoGenerated/templates"

TemplatePattern.画面のURL.売上詳細({ 売上SEQ: ':id' })   // "/uriage/edit/:id"
```

- 引数の位置に、渡された文字列を変換せずにそのまま置きます。引数はすべて文字列で受け取ります。
- 変換を使わないので、利用者が入力した値など、任意の値を渡す用途には使わないでください。
- 種類によらず、すべてのテンプレート文字列に生成されます。
- C# には生成されません。サーバーでルート定義のようなパターン文字列を作る場面が無いためです。
