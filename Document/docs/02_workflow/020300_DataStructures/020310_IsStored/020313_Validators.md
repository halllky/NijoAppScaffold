# バリデーション

永続化されるデータ構造の属性に特定の XML 属性を付与することで、新規登録・更新コマンドのバリデーションが自動的に生成されます。
また、DB レベルの制約も同時に付与されます。

必須・最大文字数・桁数のチェックは、生成されたコマンドが項目ごとに `AutoGeneratedDbContext` の抽象メソッドを呼ぶ形で生成されます。
チェックの中身は `OverridedDbContext` でオーバーライドして実装します（[チェックの中身の実装](#チェックの中身の実装)）。

## バリデーションが実行されるタイミング

バリデーションは[コマンド](./020312_CRUDMethods.md)の `TryValidate()` を呼んだときに実行されます。

```
コマンドの値を設定
↓
TryValidate()【自動バリデーション（このページの内容）】
↓
全経路で守るべきルールや、ユースケース固有のチェック（手動実装）
↓
エラーがあれば中断
↓
TrySaveAsync（DB への保存）
```

エラー内容は例外ではなく、メッセージコンテナオブジェクトに格納されて返されます。
`TryValidate()` はコマンドの状態を変更しません。

## バリデーション属性一覧

### IsKey / IsNotNull — 必須チェック

`IsKey="true"` または `IsNotNull="true"` が付いている項目は必須入力として扱われます。

| XML 属性           | 適用対象                               | 説明                                |
| ------------------ | -------------------------------------- | ----------------------------------- |
| `IsKey="true"`     | Root・Children の ValueMember / ref-to | 主キー。必須入力 + DB NOT NULL 制約 |
| `IsNotNull="true"` | 永続化されるデータ構造の ValueMember / ref-to      | 必須入力 + DB NOT NULL 制約         |

```xml
<Order IsStored="True" DisplayName="受注">
  <OrderId     IsKey="true"     DisplayName="受注番号" />   <!-- 必須 -->
  <CustomerRef Type="ref-to:Customer" IsNotNull="true" DisplayName="得意先" />  <!-- 必須 -->
  <Note        DisplayName="備考" />                         <!-- 任意 -->
</Order>
```

**生成されるチェック:**
```csharp
if ((errorMessage = _dbContext.ValidateRequired(this.OrderId, "受注番号")) is not null) {
    messages.OrderId.AddError(errorMessage);
}
```

ref-to の場合は、参照先のキーの項目ごとに `ValidateRequired` を呼び、最初に返ったエラーメッセージを採用します。

:::note シーケンス（自動採番）の場合
`SequenceName` が指定された項目はシステムが自動採番するため、新規登録コマンドにはその項目がありません。
更新時は null チェックが行われます。
:::

---

### MaxLength — 最大文字数チェック

文字列項目に付与します。DB のカラム長制約も同時に生成されます。

```xml
<Customer IsStored="True" DisplayName="得意先">
  <CustomerId IsKey="true"                DisplayName="得意先コード" />
  <Name       IsNotNull="true" MaxLength="100" DisplayName="得意先名" />
  <Phone      MaxLength="20"              DisplayName="電話番号" />
</Customer>
```

**生成されるチェック:**
```csharp
if ((errorMessage = _dbContext.ValidateMaxLength(this.Name, 100, "得意先名")) is not null) {
    messages.Name.AddError(errorMessage);
}
```

---

### TotalDigit / DecimalPlace — 桁数チェック

数値型（int / long / decimal）の項目に付与します。

| XML 属性           | 説明                                                                                |
| ------------------ | ----------------------------------------------------------------------------------- |
| `TotalDigit="N"`   | 整数型の場合: 10^N 未満であること。decimal の場合: 整数部と小数部を合わせた最大桁数 |
| `DecimalPlace="M"` | decimal のみ。小数部の最大桁数（`TotalDigit` と組み合わせて使用）                   |

```xml
<OrderDetail Type="children" DisplayName="受注明細">
  <Quantity   IsKey="true"  TotalDigit="5"              DisplayName="数量" />       <!-- 最大 99999 -->
  <UnitPrice  IsNotNull="true" TotalDigit="10" DecimalPlace="2" DisplayName="単価" />  <!-- 最大 99999999.99 -->
</OrderDetail>
```

**生成されるチェック:**
```csharp
if ((errorMessage = _dbContext.ValidateDigitsAndScales(this.UnitPrice, 10, 2, "単価")) is not null) {
    messages.UnitPrice.AddError(errorMessage);
}
```

整数型の項目も decimal に変換して渡されます。整数型の項目の `DecimalPlace` には常に 0 が渡されます。

### チェックの中身の実装

必須・最大文字数・桁数のチェックの中身は、`AutoGeneratedDbContext` の抽象メソッドとして生成されるので、`OverridedDbContext` でオーバーライドします。
スキーマ定義にかかわらず常に生成され、新規プロジェクトのテンプレートには次の内容の初期値が `Core/OverridedDbContext.Validation.cs` に入っています。
null を返すとチェックOK、文字列を返すとその内容でエラー登録されます。

| メソッド                                                          | テンプレートの初期値                                                                              |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `ValidateRequired(value, displayName)`                            | null と、空白だけの文字列を未入力とみなす                                                         |
| `ValidateMaxLength(value, maxLength, displayName)`                | `StringInfo.LengthInTextElements` で数える（絵文字などのサロゲートペアや結合文字も1文字）          |
| `ValidateDigitsAndScales(value, totalDigit, decimalPlace, displayName)` | 整数部が `totalDigit - decimalPlace` 桁を超えるか、小数部が `decimalPlace` 桁を超えたらエラー |

DB の製品が文字列の長さを数える単位（UTF-16 の単位など）に合わせたい場合などは、この実装を書き換えます。

```csharp
partial class OverridedDbContext {
    public override string? ValidateMaxLength(string? value, int maxLength, string displayName) {
        return value?.Length > maxLength
            ? MSG.MaxLengthError(displayName, maxLength.ToString())
            : null;
    }
}
```

### エラーの文言

自動生成されたコードは、エラーの文言を持ちません。
文言が要る箇所では `AutoGeneratedDbContext` の抽象メソッドを呼び、`OverridedDbContext` がオーバーライドして文言を返します。
上のチェックのメソッドのほかに、次のメソッドがあります。

| メソッド                                           | 呼ばれるとき                                                         |
| -------------------------------------------------- | -------------------------------------------------------------------- |
| `GetConcurrencyErrorMessage()`                     | 更新・削除のコマンドが、読み込んだ後に他のユーザーの更新を検出したとき |
| `GetGenericLookupValueNotFoundMessage(displayName)` | 汎用参照テーブルに存在しない区分値が指定されたとき                     |

新規プロジェクトのテンプレートでは、文言を nijo.xml のテンプレート文字列のグループ `MSG` に定義し、オーバーライドしたメソッドからそれを返しています。
文言を変えるときは、`MSG` を書き換えます（[テンプレート文字列](../../020700_Constants/020704_Templates.md)）。

---

### 汎用参照テーブルの存在チェック

`ref-to` で汎用参照テーブル（`IsGenericLookupTable="true"`）を参照している場合、
指定された区分値がテーブルに存在するかどうかのチェックが自動生成されます。

詳細は [汎用参照テーブル](../../020700_Constants/020703_GenericLookupTable.md) を参照してください。

## カスタムバリデーション

スキーマ定義では表現できない複雑なバリデーションは、`TryValidate()` が返すメッセージコンテナに追記する形で手動実装します。

```csharp
private static void Validate受注(OrderCreateCommand command, OrderSaveCommandMessages messages) {

    // 受注日が未来日でないかチェック
    if (command.OrderDate > DateTime.Today) {
        messages.OrderDate.AddError("受注日に未来日は指定できません。");
    }

    // 明細の合計数量チェック
    var totalQty = command.OrderDetails.Sum(d => d.Quantity) ?? 0;
    if (totalQty > 9999) {
        messages.AddError("合計数量が上限を超えています。");
    }
}
```

```csharp
command.TryValidate(out var validated, out var errors);
Validate受注(command, errors);
errors.CopyTo(messages);

if (validated == null || messages.HasError()) return;
```

:::note どこに書くか
- **このデータ構造が関係するどのユースケースからの更新でも守られるべきルール** → 名前付きのメソッドに切り出し、そのデータ構造を保存するすべてのコマンドから呼ぶ
- **特定のユースケースでのみ適用されるルール** → コマンドの処理の中に実装
:::

### カスタム属性による検証

`IsValidation` が指定されたカスタム属性を付与した項目には、検証フックが生成されます。
フックは `AutoGeneratedDbContext` の抽象メソッドとして項目の型ごとに生成されるので、`OverridedDbContext` で1回オーバーライドすれば、その属性が付与されたすべての集約の項目に適用されます。

```csharp
partial class OverridedDbContext {
    public override string? ValidateNotNegative(decimal? value, PropertyInfo propertyInfo) {
        return value < 0m ? "負の値は許可されていません。" : null;
    }
}
```

## バリデーションエラーのメッセージ構造

エラーメッセージはネストした構造を持ちます。Children（明細行）のエラーは行番号付きで管理されます。

```
OrderSaveCommandMessages
  ├─ OrderId       → エラーメッセージリスト
  ├─ CustomerRef   → エラーメッセージリスト
  └─ OrderDetails
       ├─ [0]
       │   ├─ LineNo  → エラーメッセージリスト
       │   └─ ...
       └─ [1]
           └─ ...
```
