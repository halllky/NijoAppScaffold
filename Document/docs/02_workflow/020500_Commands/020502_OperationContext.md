# OperationContext

コマンドの `Execute{Name}Async` メソッドは、次の形をしています。

```csharp
public override async Task<戻り値の型?> Execute{Name}Async(
    引数の型 param,                 // 処理の入力
    引数のメッセージの型 messages,   // 処理の出力のうち、引数の形に沿ったエラー・情報メッセージ
    OperationContext context)     // この呼び出しについての、全処理に共通の入出力
```

1回の呼び出しの情報は、性質ごとに次のように分かれています。

| 情報 | 受け渡し方 | 形を決めるもの |
|---|---|---|
| 入力 | 引数 `param` | スキーマ定義の `Parameter` 属性 |
| 戻り値 | メソッドの戻り値（`return`） | スキーマ定義の `ReturnValue` 属性 |
| エラー・情報メッセージ | 引数 `messages` | 引数の形 |
| 全処理に共通の入出力（検証専用モード、確認メッセージなど） | 引数 `context` | アプリケーション（`OperationContext` クラス） |

引数のないコマンドは `param` が無く、`messages` は `MessageSetter` 型になります。戻り値のないコマンドは `Task` を返します。

## OperationContext とは

自動生成されるアプリケーションサービスは `AutoGeneratedApplicationService<TOperationContext>` という型引数つきのクラスで、
各処理はこの型引数の型のインスタンスを `context` として受け取ります。
Nijo はこの型の中身を一切参照しません。中身はアプリケーションが決め、型引数にはアプリケーションが定義したクラスを指定します。

```csharp
public partial class OverridedApplicationService : AutoGeneratedApplicationService<OperationContext> {
```

テンプレートの `Core/OperationContext.cs` には、Web アプリケーションでよく使う2段階の確認（後述）のためのプロパティが定義されています。
呼び出しのたびに呼び出し元が新しいインスタンスを作って渡し、処理の終了後に中身を読みます。
ログインユーザーや現在時刻のように、呼び出しが何回あっても同じ値になるものはここに入れず、DI から取得します。

## Messages（エラー・情報メッセージ）

### 操作レベルのメッセージ

フォーム全体に関わるエラーや、処理完了後の通知メッセージを設定します。

```csharp
// 権限がない場合のエラー（戻り値のあるコマンドなので null を返して中断）
if (LoginUser == null || !LoginUser.CanUse入荷登録) {
    messages.AddError("入荷担当のみ実行可能です。");
    return null;
}

// 処理成功後の通知
messages.AddInfo("入荷登録が完了しました。");

// エラーが1件でもあるか確認
if (messages.HasError()) return null;
```

### フィールドレベルのメッセージ

特定の入力項目に対してエラーを紐付けます。

```csharp
// ログイン処理の例
if (string.IsNullOrWhiteSpace(param.従業員番号)) {
    messages.従業員番号.AddError("従業員番号を入力してください。");
}
if (string.IsNullOrWhiteSpace(param.パスワード)) {
    messages.パスワード.AddError("パスワードを入力してください。");
}
if (messages.HasError()) return;
```

### コレクション要素のメッセージ

明細行など繰り返し要素の各行にエラーを紐付けます。
`messages.コレクション名[i]` でその行専用のメッセージコンテナを取得します。

```csharp
// 売上明細の一覧を検証する例
for (var i = 0; i < param.売上詳細の売上明細.Count; i++) {
    var detail = param.売上詳細の売上明細[i];
    var message = messages.売上詳細の売上明細[i]; // i 行目のメッセージコンテナ

    if (detail.商品.商品SEQ == null) {
        message.商品.AddError("商品を選択してください。");
        continue;
    }
    if (detail.売上数量 == null || detail.売上数量 <= 0) {
        message.売上数量.AddError("売上数量は1以上の整数を入力してください。");
        continue;
    }
}

// 全行のチェックが終わった後で、エラーがあれば中断
if (messages.HasError()) return;
```

## ValidationOnly（2フェーズ検証）

保存前にユーザーへ「本当に実行しますか？」という確認を求めたい場面があります。
このために、コマンドの呼び出しは内部的に2フェーズで実行されることがあります。

- **フェーズ1（`ValidationOnly = true`）**: バリデーションのみ実行し、問題がなければ確認メッセージを積む。実際の保存はしない。
- **フェーズ2（`ValidationOnly = false`）**: ユーザーが確認した後に実際の保存処理を実行する。

```csharp
public override async Task Execute売上修正Async(
    売上詳細DisplayData param,
    売上詳細Messages messages,
    OperationContext context) {

    // ─── バリデーション ───
    if (param.売上SEQ == null) {
        messages.AddError("売上SEQが指定されていません。");
        return;
    }
    // ... 明細のチェック ...

    if (messages.HasError()) return;

    // フェーズ1: 確認メッセージを積んで終了（実際の保存はしない）
    if (context.ValidationOnly) {
        context.Confirms.Add("修正を確定します。よろしいですか？");
        return;
    }

    // フェーズ2: ここから実際の保存処理
    await using var tran = await BeginTransactionAsync();
    // ...
    await tran.CommitAsync();
}
```

:::note `ValidationOnly` と `Confirms` はアプリケーションの定義です
`ValidationOnly` と `Confirms` は Nijo が生成するものではなく、テンプレートの `OperationContext` に定義されたプロパティです。
確認メッセージを画面で利用者に見せるのか、定周期バッチのように無視して続行するのかは、処理ではなく呼び出し元が決めます。
:::

## 戻り値

処理結果はメソッドの戻り値として返します。
エラーで処理を中断する場合や、検証専用モードで処理を終える場合は `null` を返して構いません。

```csharp
// 入荷登録の例: 発番した入荷ID を戻り値として返す
await tran.CommitAsync();
messages.AddInfo("入荷登録が完了しました。");
return new() { 入荷ID = newId };
```

```csharp
// ログインの例: 権限がなければ null を返して中断する
if (employee == null) {
    messages.AddError("従業員番号またはパスワードが違います。");
    return null;
}
await tran.CommitAsync();
return LoginUser.From(employee).ToDisplayData();
```

## トランザクションとの組み合わせパターン

[登録・更新・削除](../020300_DataStructures/020310_IsStored/020312_CRUDMethods.md) の部品は `messages` を受け取りません。
検証結果や保存結果のメッセージは、コマンドの処理の中で `CopyTo` により `messages` へ移します。

```csharp
// 検証
var header = DbContext.StartCreating入荷();
header.入荷ID = newId;
header.TryValidate(out var validatedHeader, out var headerErrors);
headerErrors.CopyTo(messages);

var details = new List<ValidatedCommand<入荷明細UpdateCommand>>();
for (var i = 0; i < param.入荷商品一覧.Count; i++) {
    var detail = DbContext.StartCreating入荷明細();
    // ...
    if (detail.TryValidate(out var validated, out var errors)) {
        details.Add(validated);
    }
    errors.CopyTo(messages.入荷商品一覧[i]);
}

if (validatedHeader == null || messages.HasError() || context.ValidationOnly) return null;

// 保存。コミットせずに return するだけでロールバックされる
await using var tran = await BeginTransactionAsync();

var headerResult = await DbContext.TrySaveAsync(validatedHeader);
if (!headerResult.Success) {
    headerResult.Errors.CopyTo(messages);
    return null;
}

var detailResult = await DbContext.TrySaveAsync(details);
if (!detailResult.Success) {
    detailResult.Errors.CopyTo(messages);
    return null;
}

await tran.CommitAsync();
messages.AddInfo("入荷登録が完了しました。");
return new() { 入荷ID = newId };
```

## 呼び出し元ごとの扱い

呼び出し元は、呼び出しのたびに `OperationContext` を作って渡し、処理の終了後に中身を自分の都合で解釈します。

| 呼び出し元 | `ValidationOnly` | 処理後の `Confirms` |
|---|---|---|
| Web | テンプレートでは常に `false`。確認を挟む場合は、確認前のリクエストで `true` にする | テンプレートでは扱わない。確認を挟む場合は、レスポンスに詰めてクライアントに確認を求める |
| 単体テスト | テストケースで指定 | 必要に応じて検証する |
| バッチ | 通常は `false` | 無視するか、ログに出すか、失敗とするかをバッチ側で決める |

ある処理の中から別のコマンドを呼ぶ場合は、同じ呼び出しの続きなので同じ `context` をそのまま渡し、メッセージは呼び出し先の引数の形に変換して渡します。
呼び出し先を別の扱い（検証専用モードを変えるなど）で呼びたい場合は、新しいインスタンスを作って渡します。

```csharp
await applicationService.Execute入荷登録Async(param, messages.As<入荷詳細Messages>(), context);
```

### Web からの呼び出し

自動生成された `Operation<OperationContext>.All` には、スキーマ定義から生成されたすべてのクエリとコマンドが、引数・戻り値・メッセージの型と URL とともに並んでいます。
テンプレートの `WebApi/Base/OperationEndpoints.cs` は、これを1件ずつ ASP.NET Core の Minimal API のエンドポイントとして登録し、HTTPリクエストと処理の引数・戻り値・メッセージ・`OperationContext` とを変換します。
クライアント側でこれを呼び出すのは `client/src/base/callOperationAsync.ts` です。

```csharp
// Program.cs
app.MapOperationEndpoints((operation, endpoint) => {
    // 処理ごとに異なる設定がある場合はここで行う。
    // 各処理は Operations<OperationContext> の static プロパティとして生成され、常に同じインスタンスなので参照で比較できる
    if (operation == Operations<OperationContext>.ログイン) {
        endpoint.AllowAnonymous();
    }
});
```

テンプレートの変換方法は最も単純なもので、引数を JSON で送り、戻り値とメッセージを JSON で受け取ります。
エラーのメッセージがあればステータスコードは `422`、無ければ `200` です。確認メッセージは扱わず、処理は常に1回のリクエストで入力チェックから更新まで行います。

```typescript
const result = await callOperationAsync('受注登録', param)
if (result.ok) {
  // result.returnValue が戻り値
} else {
  // result.messages にエラーなどのメッセージが入っている
}
```

変換方法（JSONの形、ステータスコードなど）はアプリ側のコードなので、サーバー側とクライアント側の整合性がとれていれば自由に変更できます。

#### 確認メッセージを挟む例

デモ101（`demo/101_販売管理システム`）は、テンプレートとは別の変換方法で、添付ファイルの送信と確認メッセージに対応しています。
サーバー側は `WebApi/OperationEndpoints.cs`、クライアント側は `client/src/http/callOperationAsync.ts` です。

1回目のリクエストは `ValidationOnly = true` で実行し、エラーが無ければ、確認メッセージと「確認が必要」を表す `requiresConfirmation: true` を返します（エラーがあればステータスコード `422`）。
利用者が承諾したら、クライアントは確認済みを表す `confirmed=true` を付けて2回目のリクエストを送り、サーバーはこれを `ValidationOnly = false` で実行します。
「確認済み（confirmed）」は画面側の、「入力チェックのみ（ValidationOnly）」は処理側の概念で、サーバーは「確認済みでなければ入力チェックのみ」として両者を対応させます。
ログインや初期表示のように確認を挟まない呼び出しは、クライアント側のオプション `{ confirmed: true }` で1回目から `confirmed=true` を付けます。

```typescript
// callOperationAsync.ts の抜粋
if (json.requiresConfirmation) {
  const confirmMessage = json.confirms.join('\n') || '処理を確定しますか？'
  if (window.confirm(confirmMessage)) {
    searchParams.set('confirmed', 'true')
    continue  // confirmed=true を付けて2回目のリクエストへ
  } else {
    return { type: 'canceled' }
  }
}
```

## OperationContext の拡張

`OperationContext` はアプリケーションのクラスなので、呼び出し1回ごとの情報を自由にプロパティとして追加できます。
処理からは型付きのプロパティとしてそのまま参照できます。

例: 処理完了後のトースト通知とページ遷移

```csharp
// Core/OperationContext.cs
public class OperationContext {
    // ...
    /// <summary>処理成功時に利用者に通知するメッセージ</summary>
    public string? ToastMessage { get; set; }
    /// <summary>処理完了後に遷移する画面のURL</summary>
    public string? RedirectUrl { get; set; }
}

// コマンドの処理
await tran.CommitAsync();
context.ToastMessage = "登録が完了しました。";
context.RedirectUrl = $"/orders/{savedId}";
```

Web から使う場合は、`OperationEndpoints.cs` でレスポンスに詰め、`callOperationAsync.ts` のレスポンスの型にも同じフィールドを追加します。
自動生成される部分ではないため、サーバーとクライアントの型の同期は手動で行う必要があります。

```typescript
const result = await callOperationAsync('受注登録', param)
if (result.ok && result.toastMessage) {
  showToast(result.toastMessage)
}
```
