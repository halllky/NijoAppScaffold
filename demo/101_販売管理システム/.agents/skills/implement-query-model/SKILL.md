# クエリモデルの実装

クエリモデルは「一覧検索 1 種類」を表す読み取り専用のモデルである。

決まりと仕組みは [標準仕様書](../../../標準仕様書.md) の「検索」の章を正とする。特に開発者向け情報の「検索処理の作り」と「DB のビューから取得する検索（MapToView）」を先に読む。
この手順書は、それを実装するときの手順と確かめ方を補うものである。標準仕様書と食い違う場合は標準仕様書に従い、食い違いをユーザーに報告する。

## 進め方

1. 自動生成された検索処理のソースを読み、実装方式を確認する。
   - 生成された `CreateQuerySource` が抽象メソッドなら「LINQ to Entities 方式」。
   - ビューを参照する実装が生成されていれば「ビュー方式」（nijo.xml で `MapToView` を指定した場合）。
   - データモデルから生成されたクエリモデルは `CreateQuerySource` の実装まで生成されているので、FROM 句・SELECT 句の実装は不要である。
2. 方式に応じて以下の節に従って実装する。C# のオーバーライドは、アプリケーションサービス（`OverridedApplicationService`）の partial class に、標準仕様書「プロジェクトの構成と業務処理の書き方」のファイルの分け方で書く。ビュー方式で C# のオーバーライドが何も無ければ C# のファイルは作らない。
3. ビルドし、実際に検索を実行して、絞り込み・並び替え・件数・ページ送りがそれぞれ正しく動くことを確かめる。

## 自動生成されたファイルは編集しない

振る舞いはオーバーライドで変える。生成物のままでは実現できない場合は、コードを歪めて回避せずユーザーに報告する。

## LINQ to Entities 方式

`CreateQuerySource` をオーバーライドし、DbContext のエンティティから検索結果の型への射影（`Select`）を書き、1 つの `IQueryable` として返す。

- 参照先の項目はナビゲーションプロパティで辿り、集計も射影の中で行う（SQL に翻訳される）。
- 射影の式は、EF Core が SQL に翻訳できるものだけで書く。SQL に翻訳できない C# のメソッド（自作メソッド、文字列整形など）を式の中で呼ばない。
- クエリの途中で `ToList` などを呼んでメモリに展開しない。子配列を持つ項目を射影の中で `.Select(...).ToList()` と組み立てるのはよい。
- 複数のデータ源を連結する場合は `Concat` / `Union` で 1 つの `IQueryable` にまとめる。
- 翻訳できるかどうかは実行時まで分からない。実際に検索を実行し、例外が出ないこと、および想定どおりの SQL が発行されていることをログで確かめる。

## ビュー方式

ビュー名・列名・キーは、生成された EF Core 設定（`ToView(...)`、`HasColumnName(...)`、`HasKey(...)`）を読んで合わせる。
ファイルの置き場所と名前の付け方は標準仕様書の「DB のビューから取得する検索（MapToView）」に従う。

ビューとの不整合はビルドで検出されないため、すべての列について絞り込みと並び替えを実行して確かめる。
