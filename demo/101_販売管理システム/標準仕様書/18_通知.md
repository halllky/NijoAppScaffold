# 18. 通知

ユーザー宛ての通知を DB に保存し、画面で一覧・既読にする。メールやチャットには送らない。ほかの業務処理やジョブから使われる機能で、使わない案件は取り外す（18.3 の「通知を使わない場合」）。

## 18.2 限界

- 宛先のユーザーを削除しても、その通知は次のクリーンナップまで残る。その間に同じ従業員番号のユーザーを作ると、そのユーザーが通知を引き継ぐ。
- すべてを既読にする操作は、未読の通知を1件ずつ保存する。未読がとても多いユーザーでは時間がかかる。件数と処理時間の関係は未計測。
- 未読の件数は画面を移動するたびに数えるので、その分のサーバーの呼び出しとログが増える。

## 18.3 主なカスタマイズ方法

### 通知を作る

- 業務処理のトランザクションの中で、アプリケーションサービスの通知を作るメソッドを呼ぶ。宛先（従業員番号の一覧）、本文、リンク先を渡す。トランザクションの外で呼ぶと例外になる（NTF-008）。
- 宛先は、通知の種類ごとに業務処理で決める（NTF-002）。見本は、デモ101の参考実装の「通知」を参照。
- リンク先は、画面の URL のオリジンを除いた部分で渡す。形式の詳細は、nijo.xml のデータモデル「通知」のリンク先の説明を参照。画面の URL は nijo.xml のテンプレート文字列から組み立てる（8.2）。
- 本文の長さが上限を超えるなど、通知として保存できない内容を渡すと例外になり、業務データも保存されない。利用者の入力をそのまま本文に入れる場合は、長さに注意する。

### メールやチャットなど外部に送る

- メールやチャットにも送る場合は、通知を作る処理に送信を追加する。
- 送信は外部システムの更新（13章）として扱うか、通知の保存の後にジョブ（19章）として送るかを選ぶ。後者なら、送信の失敗が業務データの保存を妨げず、失敗したものを後から確認できる。

### 通知を使わない場合

次のものを削除する。通知の機能の外から参照しているのは、クリーンナップの処理だけである。

- nijo.xml のデータ構造「通知」「通知一覧」「通知既読設定Parameter」「未読通知件数ReturnValue」と、コマンド「通知既読設定」「通知すべて既読」「未読通知件数」。削除したら再生成する。
- Core の通知のフォルダと、通知の単体テスト。
- 画面の P003 通知のファイル。ナビゲーションの項目と未読の件数の表示も、これで消える。
- クリーンナップの処理の中の、通知を削除する呼び出し。
- ダミーデータの、管理者宛ての通知。
- 通知のテーブルを削除するマイグレーションを追加する。

通知を使う処理があれば、それも外す。ジョブを使っている場合は、ジョブの結果を記録する処理の中にある、終了の通知（JOB-010）を作る呼び出しも外す。

## 18.4 開発者向け情報

- 通知は1つのテーブルに、宛先のユーザー・本文・リンク先・既読の日時をもつ。作成の日時には、すべてのデータモデルにある作成日時の列（UPD-001）を使う。既読の日時が空なら未読である。
- 宛先は1行につき1人である。複数人に送るときは1人ずつ行を作る。全員に宛てた1行をもたないのは、既読をユーザーごとに管理するため。
- 宛先は従業員番号の文字列で持ち、ユーザーへの外部参照にしない。外部参照にすると、未読の通知が残っているユーザーを削除できなくなるため。その代わり、宛先のユーザーがいない通知はクリーンナップで削除する（NTF-007）。
- リンク先は、画面の URL のオリジンを除いた部分を文字列で保存する。NTF-003 の備考の制約はこのため。"/" で始まり、"//" や "/\" で始まらないことを、通知を作るときと、画面でリンクとして表示する前の両方で確かめる（NTF-009）。
- 通知の一覧・既読と未読の切り替え・すべて既読・未読の件数の処理は、どれもログインユーザー宛ての通知だけに絞る共通の処理を通す（NTF-005）。他のユーザー宛ての通知を指定されたときは、存在しない通知と同じエラーにし、存在することも知らせない。
- 既読と未読の切り替えの楽観排他（UPD-004）には、画面が読み込んだ時点ではなく、処理の中で読み込んだ時点のバージョンを使う。書き込むのは宛先の本人だけで、後から書いた方が勝っても困らないため。
- 未読の件数は、画面の移動のたびにサーバーに問い合わせる（NTF-004）。宛先と既読の日時のインデックスを、DB へのアクセスを担う手書きのクラスで定義している。nijo.xml では一意でないインデックスを定義できないため。
- ナビゲーションの項目には、件数などを表示する部品を画面のファイルから指定できる。アプリの枠は通知のことを知らないので、通知の画面のファイルを削除すれば件数の表示も消える（8.2）。
- 画面で既読・未読を変えたら、同じ画面に移動し直す。一覧の検索と、未読の件数の取り直しの両方がそれで行われる。
