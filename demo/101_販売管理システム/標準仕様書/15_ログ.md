# 15. ログ

アプリケーションが出力するログについて、出力先、ログファイルに残るもの、1行の項目、保存期間、マスキングを扱う。認証や権限のように、ほかの章が扱う出来事のログは、その章にある。それらは表「補足：ほかの章にあるログの仕様」から辿れる。

ログは、サーバーのコンソール（標準出力）と、サーバーのフォルダに置くログファイルに出力する。ログファイルの1行には、本文のほかに、ログインユーザー ID と処理1回分の識別子が付く。これらを手がかりに、ある利用者の操作や、1回のリクエストのログを抜き出せる。処理1回分の識別子は、予期しない例外のときに画面に表示する問い合わせ番号（API-005）と同じ値である。

ログにはレベルがある。この文書では、軽いほうから Trace、Debug、Info、Warning、Error と書く。ログファイルとコンソールには、それぞれ TRACE、DEBUG、INFO、WARN、ERROR と出る。最も重いレベルは FATAL と出る。Error 以上のログは、運用担当者にメールで知らせる（ALR-001）。

## 15.1 外部仕様

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| LOG-001 | ログを、コンソールとログファイルに出力する。どのログをどちらに出力するかは、表「LOG-001 ログの出力先」のとおりで、本番環境と開発環境で変わらない。ログファイルは日ごとに分け、ファイル名はサーバーの OS のタイムゾーンでの日付にする（例：`2026-11-21.log`）。ログファイルを置くフォルダは、設定ファイルの `LogDirectory` で指定する。相対パスは、設定ファイルのあるフォルダからの相対パスになる | 検査 | 運用・保守性 | コンテナのようにコンソールの出力を集める動かし方と、Windows のサービスのようにコンソールの出力が残らない動かし方の、どちらでも後から調べられるようにするため。設定ファイルの `Logging` の区画（ASP.NET Core の標準のレベルの設定）は効かない |
| LOG-002 | ログファイルの1行は、表「LOG-002 ログファイルの項目」の項目を、この順にタブで区切ったものである。文字コードは UTF-8 である。本文や例外が改行を含むときは、1件のログが複数の行にわたる。コンソールの1行は、日時・レベル・ロガー名・本文と例外を「\|」で区切ったもので、ログインユーザー ID・処理名・処理1回分の識別子は出ない。コンソールの日時には、タイムゾーンのオフセットが付かない | 検査 | 運用・保守性 | 日時にオフセットを付けるのは、サーバーの OS のタイムゾーンが業務のタイムゾーン（ENV-004）と違っても、データの日時と突き合わせられるようにするため |
| LOG-003 | Web からの処理（HTTP のリクエスト1回）では、処理名は URL のパス（例：`/api/x7cda55dc0744dd2c61802153d4af8aed/execute`）で、処理1回分の識別子はリクエストごとに振る。ログインユーザー ID は、リクエストを受けた時点のログインユーザーである | 検査 | 運用・保守性 | 識別子の形は API-005 による。ジョブの場合は JOB-011、テンプレートの外のバッチの場合は 18.3 |
| LOG-004 | カスタム属性「マスキング」を付けた項目（パスワードなど）は、オブジェクトを JSON にしてログに出力するとき（LOG-009 の引数など）に、値を `***` に置き換える。本文の文章に直接埋め込んだ値と、保存したデータのキー（LOG-009）は、マスキングされない | 検査 | セキュリティ | どの項目に付けるかは nijo.xml で指定する。エラーの通知のメール（ALR-007）にも、マスキングした後の内容が載る。キーに付けた例は、セッションのセッションキーのハッシュ値である（SES-001） |
| LOG-006 | ログファイルは、およそ30日分を残す。ログファイルを開くとき（起動した後と、日付が変わった後の、最初の書き込み）に、ログのフォルダにある拡張子 `.log` のファイルを、更新日時の新しいほうから30個だけ残し、それより古いものを削除する。当日のファイルを新しく作るときは、作る前に30個に減らすので、当日のファイルを含めて31個になる | 検査 | 運用・保守性 | 日数ではなくファイルの数で数えるので、ログを出力しなかった日（サーバーを止めていた日など）があると、30日より前のファイルも残る。ログのフォルダに置いた、ログファイルではない `.log` のファイルも、数に入れて削除する |
| LOG-007 | HTTP のリクエストごとに、処理が終わったときに、メソッド・パス・処理時間・応答の状態コードを Info でログに出力する（例：`POST /api/…/execute 完了: 70ms, Status: 422`）。死活の確認（OPS-001）と、画面の JavaScript や CSS などの静的なファイルの配信は対象外である | 検査 | 運用・保守性 | 本番環境で「遅い」「エラーになった」という問い合わせを調べるため |
| LOG-008 | 起動の途中で例外が起きてサーバーが止まるときは、その例外を FATAL でログに出力してから止まる | 実演 | 運用・保守性 | 起動しない理由を、ログファイルで調べられるようにするため。ログの設定が終わる前（設定ファイルの読み込みなど）に起きた例外は、標準エラー出力にだけ出る |
| LOG-009 | 画面から処理（検索と更新）を呼び出したときは、その引数を Debug でログに出力する。DB に発行した SQL を、Debug でログに出力する。SQL のパラメーターの値は出力しない。データを保存したときは、データ構造の名前、操作（新規登録・更新・削除）、キーを Info でログに出力する | 検査 | セキュリティ | 本番環境でもログファイルに残る（LOG-001）。そのため、ログファイルには、利用者が入力した業務のデータ（個人情報を含むことがある）が残る。保存に失敗したときのログのレベルは 9.2 による |

### LOG-001 ログの出力先

| ログ | コンソール | ログファイル |
|---|---|---|
| ASP.NET Core と Entity Framework Core のログ（ロガー名が `Microsoft.AspNetCore.` か `Microsoft.EntityFrameworkCore.` で始まるもの） | すべてのレベル | Warning 以上 |
| それ以外のログ（テンプレートと案件の処理のログと、ほかのフレームワークのログ） | すべてのレベル | すべてのレベル |

### LOG-002 ログファイルの項目

| 項目 | 内容 |
|---|---|
| 日時 | サーバーの OS のタイムゾーンの時刻に、そのオフセットを付けたもの（例：`2026-11-21 08:29:44.5829+09:00`） |
| レベル | TRACE、DEBUG、INFO、WARN、ERROR、FATAL のいずれか |
| ログインユーザー ID | ログを出力した処理のログインユーザーのユーザー ID（従業員番号）。ログインユーザーがいなければ空 |
| 処理名 | Web からの処理では URL のパス（LOG-003）、ジョブではジョブの種類（JOB-011）。どの処理にも属さないログ（起動と停止、ジョブの待ち受けなど）では空 |
| 処理1回分の識別子 | Web からの処理ではリクエストごとに振った値（LOG-003）、ジョブではジョブ ID（JOB-011）。どの処理にも属さないログでは空 |
| ロガー名 | ログを出力したクラスの名前（例：`MyApp.OverridedDbContext`） |
| 本文 | ログの本文 |
| 例外 | ログに付けた例外の種類、メッセージ、スタックトレース。例外がなければ空 |

## 15.2 限界

- ログファイルはサーバーごとに出力される。サーバーが複数台のときのログの集約は、案件で行う。
- 処理1回分の識別子は、問い合わせ番号として伝えやすいよう短くしているので（API-005）、すべての処理を通して一意とは限らない。ログを探すときは、日時と合わせて探す。
- 自動生成の処理の URL のパスは英数字の識別子なので（LOG-003）、ログの処理名からはどの処理かが分からない。処理の日本語の名前との対応は、開発者がソースで調べる。
- コンソールの出力には、ログインユーザー ID・処理名・処理1回分の識別子が出ない（LOG-002）。コンテナなどでコンソールの出力だけを集めると、問い合わせ番号からログを探せない。ログファイルも集めるか、コンソールの出力の形式を変える（15.3）。
- ASP.NET Core と Entity Framework Core のログのうち Warning より低いものは、コンソールにだけ出力する（LOG-001）。本番環境で必要な場合は、サーバーの起動の方法（サービス、コンテナなど）に合わせてコンソールの出力を受け取る。
- 出力するレベルと出力先、保存するファイルの数は、設定ファイルでは変えられない。変えるにはプログラムを改修する（15.3）。
- ログファイルの大きさの上限はない。Debug の SQL（LOG-009）を含むので、利用の量に応じて大きくなる。ディスクの空きは、死活の確認でも確かめない（OPS-001）。ログファイルに書き込めないとき（ディスクの空きがないなど）は、ログは失われる。そのときの NLog 自身のエラーは、ログのフォルダの `NLog.Fatal.log` に書こうとする。
- Warning 以下のログを運用担当者に知らせる仕組みはない（Error 以上は ALR-001）。ログインの一時ロックの始まり（AUTH-010）、権限のない処理の呼び出し（AUZ-010）、本番環境でのモックの使用（EXT-004）のように、Warning で出力する出来事に気付くには、ログを定期的に調べる仕組みや手順を案件で用意する。
- ログは保存期間（LOG-006）を過ぎると消えるので、操作ログ・監査ログの代わりにはならない（1.5）。データの変更の記録を残す方法は 11.3 にある。

## 15.3 主なカスタマイズ方法

### 出力先・レベル・形式・保存期間を変える

- ログの設定は `Core/Logging.cs` にまとめている。出力先ごとのレベル（LOG-001）、ログファイルの項目（LOG-002）、残すファイルの数（LOG-006）は、ここで変える。
- コンテナなどでコンソールの出力だけを集める場合は、コンソールの出力の形式を、ログファイルと同じ項目にする（15.2）。
- SQL のログ（LOG-009）が要らない場合は、DbContext（`OverridedDbContext`）で SQL を Debug で出力し直す設定を外す。SQL は、Entity Framework Core 自身のログ（Info）としてコンソールにも出ているので、ログファイルに出なくなるだけである。

## 15.4 開発者向け情報

- 業務処理からは、アプリケーションサービスの `Log` でログを出力する。オブジェクトを出力するときは、`SerializeForLog` で JSON にする。マスキング（LOG-004）は、これを通したときだけ効く。
- ログの出力は NLog だけで行う。ASP.NET Core が既定で登録するコンソールなどへの出力は外している。残すと、NLog のコンソール出力と二重になるため。設定ファイルの `Logging` の区画が効かないのは、NLog が Microsoft.Extensions.Logging のレベルの絞り込みを外すためである。
- NLog の設定は、NLog 全体の設定ではなく、DI コンテナごとに作る LogFactory に対して行う。並列に動く単体テストのように、同じプロセスで複数の DI コンテナを作っても、ログの出力先が互いに影響しないようにするため。WebApi は LogFactory を自分で作って DI の設定に渡し、DI コンテナを作る前に起きた例外もそれに出力する。それ以外（単体テスト、マイグレーション）では DI の設定が LogFactory を作り、DI コンテナを破棄したときに閉じる。単体テストは、テストの実行の終わりに、テストケースごとに作った DI コンテナをまとめて破棄する。
- WebApi は、起動から終了までの処理全体を例外の捕捉で囲む（LOG-008）。終了するときは、書き込まれていないログをファイルに出し切る。
- Web のリクエストごとに、ログインユーザー ID・処理名・識別子をログに付ける。これらを付ける共通の処理は、予期しない例外をログに出力する共通の処理より先に動くよう登録している。逆にすると、予期しない例外のログにこれらが付かない。
