## 24.3 外部仕様：エラーの通知

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| ALR-001 | Error 以上のログを、運用担当者にメールで知らせる | テスト | | ERR-001 |
| ALR-002 | メールは既定の宛先に送る。ログを出力するときに宛先の区分を付けた場合は、その区分の宛先にも送る。宛先の区分と宛先は設定で決める | テスト | | 既定の宛先が1件もなければ、起動を止める（CFG-004）。誰にも届かない状態で運用するのを防ぐため。例えば、商品管理システムとの連携で起きたエラーのログに、商品管理システムの担当者の区分を付ける |
| ALR-003 | WebApi では、宛先の区分ごとに、短い時間に送るメールの数を抑える。直前の一定時間に1通も送っていなければ、すぐに送る。その一定時間に出力された Error 以上のログは貯めておき、時間が経ったときに1通にまとめて送る。まとめた1通には、件数の合計と、最初の数件の内容を載せる | テスト | | DB に接続できないときのような横断的なエラーで、大量のメールが届くのを防ぐため。一定時間は設定で決める |
| ALR-004 | WebApi の外で動かすバッチでは、メールの数を抑えず、Error 以上のログをすぐに送る | テスト | |  |
| ALR-005 | メールの送信は、実機とモックを設定で切り替える。設定を省略したときは起動を止める（EXT-003） | 検査 | | 開発中に誤ってメールを送るのを防ぐため。モックは、宛先・件名・本文を書いたテキストファイルを、1通につき1つ作る |
| ALR-006 | 実機の送信は実装していない。設定で実機を選ぶと、アプリケーションは起動しない | 実演 | | 送信の方法（ライブラリ、メールサーバー）は案件で決める。実機を選んだまま、気付かずにメールが届かない状態で運用するのを防ぐため |
| ALR-007 | メールの本文には、ログの日時・レベル・ログインユーザー ID・処理名・処理1回分の識別子・本文・例外を載せる | 検査 | | ログのマスキング（LOG-005）は、メールにも適用される |
| ALR-008 | メールの送信は、業務処理のトランザクションに参加しない。送信に失敗しても業務処理には影響せず、失敗は Warning としてログに出力する | 検査 | | Error として出力すると、それがまたメールの対象になるため |

ALR-003 の例：一定時間を10分とする。10時から10時30分まで DB に接続できない状態が続くと、メールは10時（最初のエラー）と、10時10分・10時20分・10時30分（直前の10分間のまとめ）の4通になる。10時30分に復旧してエラーが止まると、10時40分に抑止が終わる。11時に再発したときは、最初のエラーをすぐに送る。

## 24.6 限界

- 本番の DB へのマイグレーションの適用は、リリースの手順に含まれない。SQL はリリース用のモジュールに入っているので、案件の手順で流す（6.3）。
- リリース用のモジュールを作る手順のスクリプトは、Windows のバッチファイルだけである。
- エラーの通知について
  - ログを出力するときに宛先の区分を付けなかったエラーは、既定の宛先にだけ送る。業務処理で例外を捕まえず、WebApi の共通の処理でログに出力された例外もこれに当たる。
  - まだ送っていないメール（ALR-003 で貯めているもの）は、サーバーのプロセスが止まるときに送る。プロセスが異常終了したときは失われる。
  - 送信に失敗したメールは、送り直さない。
  - バッチで1件ごとに Error のログを出力すると、件数分のメールが届く（ALR-004）。
  - 送る数を抑える処理（ALR-003）はサーバーごとに行うので、サーバーが複数台のときは、横断的なエラーで台数分のメールが届く。

## 24.7 主なカスタマイズ方法

### エラーの通知の実機を実装する

- メールを送る部品のインターフェース（`IErrorMailSender`）を実装したクラスを作り、設定で実機を選んだときに使う。エラーの通知を作る処理で起動を止めている部分（ALR-006）を、この実装に置き換える。
- 実機の送信は、送るスレッドから呼ばれる。送信に時間がかかっても業務処理は待たされないが、次のメールの送信は遅れる。
- サーバーが止まるときは、まだ送っていないメールを、その場で送り終えてから止まる（24.6）。メールサーバーの応答が遅いと止まるまでに時間がかかるので、実機の送信には時間の上限を設ける。

### エラーの通知の宛先の区分を追加する

- 設定に宛先の区分と宛先を追加し、その担当者が知るべきエラーのログを出力するときに、その区分を付ける。区分は、ロガーの拡張メソッド（`BeginErrorNotificationCategory`）で、ログのスコープとして付ける。

## 24.8 開発者向け情報

- 死活の確認は、ASP.NET Core のヘルスチェックの機能に、DB への接続の確認を1つだけ登録し、ログイン不要として公開する。ロードバランサーなどから短い間隔で呼ばれるので、リクエストごとのログ（LOG-007）は出さない。
- バージョン番号は、プロジェクトのフォルダの直下の `VERSION` ファイルに書く。サーバーと画面のビルドは、どちらもこのファイルを読む。
- サーバーのバージョンは .NET のアセンブリの情報バージョンとして埋め込み、コミットの識別子は .NET SDK がビルドのときに付ける。画面のバージョンは、画面のビルドのときに同じバージョン番号とコミットの識別子を埋め込む。サーバーは、起動のときにもバージョンをログに出す。
- エラーの通知は、ログの出力の仕組み（NLog）に、Error 以上のログを受け取る出力先を追加して行う。出力先は、ログを出力した時点で、ログファイルの1行と同じ情報を文字列にして渡す。画面からの処理を待たせないよう、受け取ったログは貯めておき、別のスレッドで1秒ごとにメールにして送る。抑止の状態は、サーバーのプロセスのメモリーに持つ。
- 既定では、ログを1件ずつすぐに送る（ALR-004）。WebApi は、起動のときに送る数を抑えるように切り替える（ALR-003）。
- いつ、どのログをメールにするかの判断は、時刻を引数で受け取る部品にまとめていて、単体テストで ALR-003 の例を確かめている。
