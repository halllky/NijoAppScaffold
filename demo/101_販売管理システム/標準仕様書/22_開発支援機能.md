# 22. 開発支援機能

開発環境でだけ使える機能を扱う。本番には現れない。

## 22.1 外部仕様

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| DEV-001 | 開発支援機能は、本番用のビルド（Release ビルドと、画面の本番用ビルド）には含まれない。ただし、サーバーの開発支援機能の一部（DB の作り直し、手書きの API の見本）は、ビルドの種類だけで判断し、環境（ENV-008）は確かめない。Debug ビルドを本番環境で動かすと、これらはログインせずに呼び出せる | 検査 | セキュリティ | 開発支援機能の API はログインせずに呼び出せるため |
| DEV-002 | 開発用のダミーデータを作る処理は、開発用のビルドにだけ含まれる。本番用の初期データを入れる仕組みはない | 検査 | | |

## 22.2 限界

- 本番環境では、必ず Release ビルドを使う。Debug ビルドを動かすと、DB を作り直す API などがログインせずに呼べる（DEV-001）。

## 22.3 開発者向け情報

### 開発支援機能の一覧

開発環境では、次の機能を使える。

- 画面上部のデバッグメニューから、DB を削除して作り直し、ダミーデータを入れる
- DB のテーブルの関係とデータを画面で確認する（DB ビューア）
- 画面の共通部品の動きを確かめる見本の画面
- API の一覧（Swagger）
- 手書きの API の見本（`/api/example`）。実行時の設定の内容を返す
- ログイン画面に、ダミーデータのシステム管理者のユーザー ID とパスワードを、あらかじめ入れておく。ダミーデータのユーザーのパスワードは、初期パスワード（PWD-004）とは別の値で、ダミーデータを作る処理に書かれている

### 本番に出さないための作り

- 画面：開発モードで動かしているときだけ、デバッグメニューと開発用の画面を登録する。
- サーバー：DB の作り直し・ダミーデータの生成・DB ビューア・手書きの API の見本は Debug ビルドにだけ含める。DB ビューアは、設定の保存だけは開発環境でなければ拒否するが、テーブルのデータの取得は拒否しない。API の一覧は開発環境でだけ有効にする。
- 本番に出す前に、Release ビルドと画面の本番用ビルドの結果で、これらが現れないことを確認する。
