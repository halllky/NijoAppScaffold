# 4. 設定

アプリケーションの実行時の設定の管理方法を扱う。設定ファイルがどこにあるかは、2章の図を参照。

## 4.1 外部仕様

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| CFG-001 | 実行時の設定は、WebApi の設定ファイル（`appsettings.json`）のアプリケーション用のセクションに書く。設定項目の一覧と意味は、設定のクラスのコメントにある | 検査 | 運用・保守性 | |
| CFG-002 | DB の接続先は名前付きのプロファイルとして複数持ち、設定で切り替えられる | 実演 | |  |
| CFG-003 | 設定は、設定ファイルにだけ書く。DB の接続文字列のような秘密の値も、平文で書く。環境変数やシークレットストアからは読まない | 実演 | セキュリティ | 秘密の値を守るには、サーバーで設定ファイルを置くフォルダのアクセス権を絞る |
| CFG-004 | 設定の項目の既定値はプログラムに持たず、設定ファイルに書く。省略できない項目が省略されていたり、値が不正だったりしたら、項目の名前を示して起動を止める | テスト | 運用・保守性 | 本番環境の設定ファイル（DPL-003）に書き忘れたまま、気付かずにプログラムの既定値で動くのを防ぐため。省略してよい項目は、設定のクラスのコメントで示す。ログの設定が終わる前に起動を止めるので、理由は標準エラー出力にだけ出る（LOG-008） |
| CFG-005 | 設定ファイルと同じフォルダに `appsettings.Development.json` があれば、環境（2章）によらず読み込み、同じ項目は `appsettings.json` の値を上書きする | 検査 | 運用・保守性 | 開発環境だけで使う設定を書くためのファイルである。本番環境に置くと、本番の設定が上書きされる |

## 4.2 限界

- ユーザー単位の設定や、画面から変える設定はない（1.5）。必要な場合は、データモデルを作るなどして実装する。
- 秘密の値を環境変数やシークレットストアから読むには、設定を読み込む処理を改修する（CFG-003）。
