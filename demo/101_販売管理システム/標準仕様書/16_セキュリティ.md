# 16. セキュリティ

特定の機能に属さない、Web アプリケーションとしての防御を扱う。HTTPS の扱い、ほかのサイトを使った攻撃（CSRF、クリックジャッキング）、画面や SQL への不正な入力（XSS、SQL インジェクション）、大量の呼び出しへの備えである。ログインや権限のように機能に属する防御は、その機能の章にある。

ほかの章にあるセキュリティに関わる仕様は、関連非機能要件の列が「セキュリティ」のものである。

## 16.1 外部仕様

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| SEC-001 | HTTP で受けた要求を、HTTPS に転送しない。応答に HSTS のヘッダー（`Strict-Transport-Security`）を付けない | 検査 | セキュリティ | 本番環境では、HTTP でアクセスするとログインできない（SES-003）。転送と HSTS は、前段の装置（ロードバランサーなど）で行うか、アプリで有効にする（16.3） |
| SEC-002 | ほかのオリジンからの呼び出しを許可するヘッダー（CORS の `Access-Control-Allow-Origin` など）を返さない。そのため、ほかのオリジンのページのプログラム（JavaScript）は、API の応答を読めず、独自のヘッダーを付けた呼び出し（SEC-007）も送れない | 検査 | セキュリティ | 画面と API が同じオリジンなので（ENV-002）、許可は要らない |
| SEC-004 | 画面は、表示する値（利用者が入力した値や DB の値など）を HTML として扱わず、文字のまま表示する。値に HTML のタグやスクリプトが含まれていても、文字として見えるだけで、実行されない | 実演 | セキュリティ | 画面に不正なスクリプトを埋め込む攻撃（XSS）を防ぐため。テンプレートの画面と、自動生成の画面の部品が対象である。画面の部品の仕組み（React）が、値を文字として表示することによる |
| SEC-005 | DB を読み書きするときは、利用者の入力などの値を SQL の文に埋め込まず、パラメーターとして DB に渡す。テンプレートの処理と、自動生成の処理が対象である | 検査 | セキュリティ | 入力で SQL を書き換えられる攻撃（SQL インジェクション）を防ぐため。部分一致などの検索で入力された「%」「_」も、普通の文字として扱う（QRY-003）。開発支援機能の DB ビューアは、入力した条件を SQL にそのまま埋め込むが、本番用のビルドには含まれない（DEV-001） |
| SEC-006 | すべての応答に、表「SEC-006 応答に付けるヘッダー」のヘッダーを付ける。エラーの応答、静的なファイル、死活の確認（OPS-001）の応答も対象である。開発環境で、画面の開発サーバーが返す応答にも付ける | 実演 | セキュリティ | 画面の枠の指定と `Referrer-Policy` が意味をもつのは画面の HTML に対してだけだが、付け漏れを防ぐため、応答の種類で付け分けない |
| SEC-007 | 本番環境では、GET・HEAD・OPTIONS 以外のメソッドの要求（処理の呼び出し、添付ファイルの一時保存など）に、`X-Requested-With` ヘッダーを必須にする。値は問わない。ヘッダーがなければ、処理を実行せず、状態コード 400 を本文なしで返す。開発環境では確かめない。CSRF のトークンは使わない | 実演 | セキュリティ | ほかのサイトのページから、ログイン中の利用者として処理を呼ばせる攻撃（CSRF）を防ぐため。ほかのサイトのページは、このヘッダーを付けて送れない（SEC-002）。画面は、サーバーを呼ぶときに必ずこのヘッダーを付ける。CSRF には、セッションキーの Cookie の SameSite 属性でも備えている（SES-002）ので、開発環境ではそれだけで防ぐ。開発環境で確かめないのは、API の一覧（22.2）から呼び出せるようにするため。拒否した要求は、LOG-007 のログに状態コード 400 で出るだけで、Warning などでは出力しない |
| SEC-008 | 応答に `Server` ヘッダーを付けない | 実演 | セキュリティ | 使っているソフトウェアを外に知らせないため。前段の装置が付けるヘッダーは、装置の側で外す。IIS の上で動かすときに IIS が付けるヘッダーも同じで、IIS の設定で外す（テンプレートでは行わない） |
| SEC-009 | ログインの一時ロック（AUTH-010）のほかに、呼び出しの回数や頻度を制限しない。要求の本文の大きさの上限は、添付ファイルの一時保存（FIL-003）を除き、ASP.NET Core の既定の 30,000,000 バイト（約 28.6MB）である | 検査 | セキュリティ | |

### SEC-006 応答に付けるヘッダー

| ヘッダー | 値 | 理由 |
|---|---|---|
| `X-Frame-Options` | `SAMEORIGIN` | ほかのサイトのページの枠（iframe）の中に、画面を表示させないため。見えないように重ねた画面を、利用者に知らずに操作させる攻撃（クリックジャッキング）を防ぐ。古いブラウザ向けで、今のブラウザは次の `frame-ancestors` に従う |
| `Content-Security-Policy` | `frame-ancestors 'self'` | 上と同じ。同じオリジンの画面の枠の中には表示できる。スクリプトやスタイルの読み込み元を制限する指定は付けない |
| `X-Content-Type-Options` | `nosniff` | 応答の中身の種類をブラウザに推測させず、テキストなどをスクリプトや HTML として扱わせないため |
| `Referrer-Policy` | `same-origin` | 画面からほかのサイトに移るときや、ほかのサイトの画像などを読むときに、画面の URL を送らないため |

## 16.2 限界

- スクリプトの読み込み元を制限する指定がないので（SEC-006）、画面に不正なスクリプトを埋め込まれたときに、その実行を止める二段目の守りがない。画面のプログラムとスタイルは画面の HTML に埋め込んでビルドしているので、読み込み元を自分のオリジンに限る指定をそのまま付けると、画面が動かなくなる。付けるには、画面のビルドの設定と、画面の部品が使うインラインのスタイルに合わせて調整する。
- 案件で、値を HTML として表示する画面（書式付きの文章を表示するなど）を作ると、SEC-004 の対象外になる。その画面で、表示する HTML を無害にする処理を加える。
- ほかのオリジンからの呼び出しを許可すると（SEC-002）、許可した相手のページからは、`X-Requested-With` ヘッダーを付けた呼び出しを送れるので、SEC-007 の CSRF の対策が効かなくなる。許可するなら、相手を信頼できるオリジンに限る。
- 大量の呼び出しによる負荷（DoS）への備えはない（SEC-009）。必要なら、前段の装置や WAF で、呼び出しの頻度や大きさを制限する。

## 16.3 主なカスタマイズ方法

### HTTPS への転送と HSTS をアプリで行う

- WebApi の起動処理に、ASP.NET Core の HTTPS への転送（`UseHttpsRedirection`）と HSTS（`UseHsts`）を、コメントにして置いている。有効にするときは、HTTPS への転送を、静的なファイルの配信など、応答を返すほかの処理より前に置く。コメントの位置のままでは、静的なファイルは転送されない。
- 前段の装置で HTTPS を終端する構成では、アプリには HTTP で届く。前段の装置から元の要求のプロトコルを受け取る設定（ASP.NET Core の Forwarded Headers）をしないと、転送が繰り返され、HSTS のヘッダーも付かない。

### 応答のヘッダーを変える

- SEC-006 のヘッダーは、WebApi の応答のヘッダーを付ける処理（`SecurityHeadersMiddleware`）と、画面の開発サーバーの設定（`client/vite.config.ts`）の2か所に書いている。開発環境では、画面の HTML を画面の開発サーバーが返すためである。変えるときは両方を変える。

## 16.4 開発者向け情報

- SEC-001、SEC-002、SEC-007 から SEC-009 に関わる設定は、WebApi の起動処理（`Program.cs`）にある。
- 手書きの SQL では、値を文字列の連結で SQL に埋め込まない。Entity Framework Core の `FromSql` や `SqlQuery` に補間文字列で渡すと、値はパラメーターになる。`FromSqlRaw` や `ExecuteSqlRaw` に値を連結した文字列を渡すと、SEC-005 が成り立たなくなる。
