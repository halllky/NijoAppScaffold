# 5. DB とマイグレーション

使う DB の製品と、DB の定義を変える手順を扱う。テンプレートは SQLite を使っているが、多くの案件では、本番用に別の DB の製品へ差し替える。

## 5.1 外部仕様

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| MIG-001 | 起動するときに、DB に適用されていないマイグレーションがあれば、開発環境以外では起動を止める。止めた理由と、適用されていないマイグレーションの名前は、ログに出力される（LOG-008）。開発環境では、同じ内容をログに Warning として出力し、起動を続ける | 実演 | 運用・保守性 | 本番の DB にマイグレーションの SQL を流し忘れたまま動かすのを防ぐため。開発環境では、起動した後に開発支援機能で DB を作り直すことがある（22章） |

## 5.2 主なカスタマイズ方法

### 本番の DB を SQLite 以外にする

- 5.3 の「DB の製品に依存している箇所」に挙げたものを、使う DB の製品に合わせて差し替える。マイグレーションはいったん全部削除して一から作り直す。
- nijo.xml の sequence 型（連番で採番する項目）を使う場合は、DB の製品に合わせた採番の設定を書く。見本はデモ101の参考実装にある（テンプレートには含まれない）。

## 5.3 開発者向け情報

### マイグレーション

- テンプレートのDB定義更新スクリプトは `dotnet-ef` の使用を前提としている。
- nijo.xml の変更、再生成、マイグレーションの追加、SQL の出力の順に行う。この順に行う手順のスクリプトがある（Task/ADD_MIGRATION.sh）。
- マイグレーションの SQL は、ファイル名の昇順で適用されるように考えてファイル名をつける。
- 汎用参照テーブル（6.5）のビューを作り直す SQL は、マイグレーションの手順の中で Management のコマンドが作る。汎用参照テーブルを使わない場合は、このコマンドと手順を削除してよい。
