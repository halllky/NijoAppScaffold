# 17. セキュリティ

特定の機能に属さない、Web アプリケーションとしての防御を扱う。他の章にあるセキュリティに関わる仕様の探し方は、17.3 に書いている。

## 17.1 外部仕様

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| SEC-001 | HTTP から HTTPS への転送と HSTS は、テンプレートでは行わない | 検査 | セキュリティ | 前段の装置（ロードバランサーなど）で行うか、アプリで有効にする |
| SEC-002 | 画面と API は同じオリジンから配信する（ENV-002）ので、CORS の設定は不要である | 検査 | セキュリティ | |
| SEC-003 | 他のサイトからの不正なリクエスト（CSRF）は、Cookie の SameSite 属性で防ぐ | 検査 | セキュリティ | |
| SEC-004 | 画面に値を表示するときは React のエスケープに任せる | 検査 | セキュリティ | |
| SEC-005 | DB へのアクセスは Entity Framework Core を通じて行い、SQL を文字列の連結で組み立てない | 検査 | セキュリティ | |
| SEC-006 | すべての応答に `X-Frame-Options: SAMEORIGIN`、`Content-Security-Policy: frame-ancestors 'self'`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin` を付ける | 検査 | セキュリティ | 他のサイトの画面の枠の中に表示させない指定は、今のブラウザが従う `frame-ancestors` と、古いブラウザ向けの `X-Frame-Options` の両方で行う。画面の枠の指定と `Referrer-Policy` が意味をもつのは画面の HTML に対してだけだが、付け漏れを防ぐため、応答の種類で付け分けない。開発環境で画面を返す開発サーバーの応答にも付ける |
| SEC-007 | 開発環境以外では、更新系の HTTP メソッドのリクエストに `X-Requested-With` ヘッダーを必須にし、付いていないリクエストは拒否する | 検査 | セキュリティ | SEC-003 に加える CSRF 対策。独自のヘッダーは、他のサイトのページからは付けられないため。開発環境では、API の一覧（23.2）から呼び出せるよう確かめない |
| SEC-008 | 応答に `Server` ヘッダーを付けない | 検査 | セキュリティ | 使っているソフトウェアを外に知らせないため。前段の装置が付けるヘッダーは、装置の側で外す |

## 17.2 限界

- CSRF のトークンによる対策は行わない（SEC-003）。必要なら追加する。
- HTML を直接埋め込む処理を書くと、SEC-004 の対象外になる。
- MapToView のビューや手書きの SQL は、SEC-005 の対象外である。
- `Content-Security-Policy` は、画面の枠の中に表示させてよい相手の指定（`frame-ancestors`）だけを付ける（SEC-006）。スクリプトやスタイルの読み込み元を制限する指定は付けない。案件で付ける場合は、画面の開発サーバーやインラインのスタイルと衝突しないよう調整が必要になる。同じオリジンの画面の枠の中に表示することは許している。

## 17.3 他の章にあるセキュリティに関わる仕様

他の章にあるセキュリティに関わる仕様は、仕様の表の関連非機能要件の列に「セキュリティ」と書いている。

## 17.4 開発者向け情報

- SEC-006 のヘッダーは、WebApi の共通の処理で、静的ファイルやエラーの応答も含めてすべての応答に付ける。開発環境では画面の HTML を Vite の開発サーバーが返すので、その設定にも同じヘッダーを書いている。ヘッダーを変えるときは両方を変える。
- `Server` ヘッダーは、Kestrel の設定で付けないようにしている（SEC-008）。
