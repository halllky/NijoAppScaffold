# 14. 権限

利用者がどの機能を使えるかを扱う。

## 14.2 限界

- 部署・拠点などによるデータ単位の権限はない。追加方法は 14.3。
- 参照検索（検索ダイアログなど、ほかのデータを選ぶための検索）は、参照先のクエリモデルの一覧検索の宣言を引き継ぐ。そのため、参照する側の画面の利用者は、参照先の一覧検索も呼び出せる。例えば、売上の画面で商品を選ぶ販売担当は、商品の一覧検索も呼び出せる。
  - 一覧検索の項目を見せたくない利用者がいる場合は、参照するための項目だけを持つクエリモデルを別に作り、そちらを参照する（従業員Ref と従業員マスタの分け方）。
  - 参照する側の処理を足したときは、参照先の宣言に、その処理の利用者の権限を足す。足し忘れは、画面でデータを選ぼうとしたときに弾かれることで分かる。
- ログインユーザーのいない呼び出し（定期実行のジョブなど）は、「ログイン不要」と「内部処理のみ」の処理しか呼び出せない。それ以外の処理をジョブから実行するときは、権限を確認する処理を経由せず、処理の本体のメソッドを直接呼ぶ（18.3）。画面から起動したジョブは、起動したユーザーをログインユーザーとして実行する（18.4）。
- 画面の表示の切り替え（AUZ-008）は、メニューと、画面ごとに処理の名前を指定して切り替えた部品に限る。指定し忘れた部品は表示されたままになるが、押してもサーバーで弾かれる（AUZ-001）。

## 14.3 主なカスタマイズ方法

### 処理を追加する

- nijo.xml で、クエリモデルまたはコマンドのルート要素に、カスタム属性「機能公開レベル」を指定する。指定しないと検証エラーになる。
  - 「ログイン不要」：ログインせずに呼び出せる。
  - 「ログインユーザー全員」：ログインしていれば誰でも呼び出せる。
  - 「権限で指定」：カスタム属性「機能利用可能権限」に指定した権限区分のいずれかを持つユーザーだけが呼び出せる。
  - 「内部処理のみ」：バッチなど、サーバーの内部からだけ呼び出す。WebAPI として公開しない。
- 処理の中に権限の確認は書かない。どこから呼ばれても、処理の本体の前に確認される（AUZ-001）。

### 権限を追加する

- nijo.xml の「権限区分」に値を追加して再生成する。
- その権限で使えるようにする処理の「機能利用可能権限」に、追加した値を足す。
- メニューは、その画面を開くのに呼ぶ処理の宣言で、自動で切り替わる。画面のボタンなど、処理を呼ぶ部品の表示は、その処理を呼び出せるかどうかで切り替える（14.4）。

### データ単位の権限を加える

- Entity Framework Core のクエリフィルターを使って追加する。
- DB へのアクセスを担う手書きのクラスで、モデルを定義する箇所に、データモデルごとに、ログインユーザーが見てよい行だけに絞る条件を付ける。
- 条件は、一覧の検索、参照先の検索、編集のための読み込みのすべてに適用される。論理削除（UPD-003）とは衝突しない。
- 手書きの SQL と、MapToView のビュー（10.3）には適用されない。ビューを使うデータ構造では、ビューの側でも絞る。
- ジョブやバッチなど、すべての行を扱ってよい処理では、条件を外して検索する。
- 書き込みは絞られない。自分の部署以外の値を指定した新規登録などは、入力チェックで別に防ぐ（AUZ-001）。

## 14.4 開発者向け情報

- 権限は、ログインユーザーの情報の一部として「権限区分」の値のリストで持ち、ログイン状態確認の戻り値で画面にも渡す。
- 処理の宣言（AUZ-007）は、nijo が生成する処理の一覧（`Operation<OperationContext>.All`）の各処理の `Metadata` に、型付きで入る。画面にも、生成される `operation.ts` の `Operation.Metadata` に同じ値が入る。
- すべてのクエリとコマンドは、どこから呼ばれても、処理の本体の前に、アプリケーションサービスの `InterceptAsync`（関門）を通る。呼び出せるかどうかの判定と、関門での確認は `Core/ログイン・認証/処理の呼び出し可否.cs` に1か所でまとめている。呼び出せない場合は例外を投げ、WebApi は 403 とメッセージを返す。
- WebApi のエンドポイントの登録（`WebApi/OperationEndpoints.cs`）は、「内部処理のみ」の処理を登録せず、「ログイン不要」の処理をログインせずに呼び出せるようにする。それ以外の処理は、ログインしていなければ 401 を返す（AUTH-009）。
- 画面は、`client/src/login/canInvoke.ts` で、サーバーと同じ規則で呼び出せるかどうかを判定する。メニューは、各画面の `navigationItem` に書いた、その画面を開くのに呼ぶ処理で切り替える。
- 単体テストでは、宣言の食い違い（「権限で指定」なのに必要な権限が無いなど）と、判定の規則を確かめる（`UnitTest/Tests/処理の呼び出し可否.cs`）。
