# 16. ログ

ログの出力先と内容を扱う。

## 16.1 外部仕様

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| LOG-001 | すべてのログをコンソールに出力する。そのうち、アプリケーションのログと、フレームワーク（ASP.NET Core、Entity Framework Core）のログの Warning 以上は、ファイルにも出力する | 検査 | | コンテナのようにコンソールの出力を集める動かし方と、Windows のサービスのようにコンソールの出力が残らない動かし方の、どちらでも後から調べられるようにするため |
| LOG-002 | ログの1行には、日時、レベル、ログインユーザー ID、処理名、処理1回分の識別子、ロガー名、本文、例外を含める。日時は、サーバーの OS のタイムゾーンの時刻に、そのオフセットを付けたものである | 検査 | | ログインユーザー ID と処理1回分の識別子で、ログを追跡できる。オフセットを付けるのは、サーバーの OS のタイムゾーンが業務のタイムゾーン（ENV-004）と違っても、データの日時と突き合わせられるようにするため |

## 16.2 限界

- ログファイルはサーバーごとに出力される。サーバーが複数台のときのログの集約は、案件で行う。
- Web からの処理の処理1回分の識別子は、問い合わせ番号として伝えやすいよう短くしているので（API-005）、すべての処理を通して一意とは限らない。ログを探すときは、日時と合わせて探す。
- フレームワークのログのうち Warning より低いものは、コンソールにだけ出力する（LOG-001）。本番環境で必要な場合は、サーバーの起動の方法（サービス、コンテナなど）に合わせてコンソールの出力を受け取る。

## 16.3 開発者向け情報

- ログの出力先・形式・ローテーション・マスキングは、Core の起動時の設定でまとめて行う。
- ログの出力は NLog だけで行う。ASP.NET Core が既定で登録するコンソールなどへの出力は外している。残すと、NLog のコンソール出力と二重になるため。
- NLog の設定は、NLog 全体の設定ではなく、DI コンテナごとに作る LogFactory に対して行う。並列に動く単体テストのように、同じプロセスで複数の DI コンテナを作っても、ログの出力先が互いに影響しないようにするため。WebApi は LogFactory を自分で作って DI の設定に渡し、DI コンテナを作る前に起きた例外もそれに出力する。
- WebApi は、起動から終了までの処理全体を例外の捕捉で囲み、捕まえた例外を最も重いレベル（FATAL）で出力してから止まる（LOG-008）。終了するときは、書き込まれていないログをファイルに出し切る。
- Web のリクエストごとに、ログインユーザー ID・処理名・識別子をログに付ける。これらを付ける共通の処理は、予期しない例外をログに出力する共通の処理より先に動くよう登録している。逆にすると、予期しない例外のログにこれらが付かない。
