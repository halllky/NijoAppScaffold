# 5. 設定

アプリケーションの実行時の設定の管理方法を扱う。設定ファイルがどこにあるかは、3章の図を参照。

## 5.1 外部仕様

| ID | 仕様 | 確認方法 | 関連非機能要件 | 備考 |
|---|---|---|---|---|
| CFG-001 | 実行時の設定は、WebApi プロジェクトの設定ファイルのアプリケーション用の区画に書き、業務処理からは型の付いた設定として参照する | 検査 | | 設定項目の一覧と意味は、設定のクラス（`RuntimeSetting`）のコメントを参照する |
| CFG-002 | DB の接続先は名前付きのプロファイルとして複数持ち、設定で切り替えられる | 実演 | |  |
| CFG-003 | アプリケーションサーバー単位の設定（DB の接続文字列など）は設定ファイル（ `appsettings.json` ）に平文で書く。 | 実演 | セキュリティ | 暗号化やシークレットストアは使っていない。よりセキュリティを強化するためには、例えばサーバーで設定ファイルが格納されているフォルダへのアクセス権限を絞ったり、 ASP.NET Core の仕組みを使って設定ファイルでなく環境変数で値を定義するなどの方法がある。 |
| CFG-004 | 設定の項目の既定値はプログラムに持たず、設定ファイルに書く。省略できない項目が省略されていたり、値が不正だったりしたら、項目の名前を示して起動を止める | テスト | | 本番環境の設定ファイル（DPL-003）に書き忘れたまま、気付かずにプログラムの既定値で動くのを防ぐため。省略してよい項目は、設定のクラスのコメントで示す。ログの設定が終わる前に起動を止めるので、理由は標準エラー出力にだけ出る（LOG-008） |

## 5.2 限界

- ユーザー単位の設定は対象外。必要な場合は独自にデータモデルを作るなどして実装する。

## 5.3 開発者向け情報

- 開発環境だけで使う設定は、開発環境用の設定ファイルに書いて、通常の設定を上書きする。ASP.NET Core の仕様（※）をそのまま使う。
  ※ `appsettings.json` と同じ階層に `appsettings.Development.json` を配置し、上書きしたい項目だけを後者に書けばそちらが優先される。
