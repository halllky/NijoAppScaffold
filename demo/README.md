# Nijo App Scaffold デモプロジェクト

## 番号

- 100～: 実用的な例
- 200～: エッジケース。主に動作確認目的

## デモ新規作成時

1. `nijo serve このREADME.mdがあるフォルダ` で開かれるGUIから、空テンプレートで新規プロジェクトを作成
2. 不要なファイルを削除
   - README.md
3. client の package.json の編集
   - nameを変更
   - devDependencies を削除。モノレポのルートの設定を援用するので
4. [VSCode設定ファイル](../nijo.code-workspace) の `"id": "demoFolder"` の箇所にフォルダ名を追加。VSCode > F1 > Run Task からのデバッグコマンド等で新規追加プロジェクトを選択できるようにする
5. [VSCode設定ファイル](../nijo.code-workspace) の `"folders"` に新規追加プロジェクトのフォルダを追加（任意）
6. [モノレポのルートのpackage.json](../package.json) に新規追加プロジェクトのclientフォルダを追加
7. .NET の整備 ... 後述※1のコマンドを参考にして、以下のことを行う。
   1. 新たに作成された `MyApp.sln` と、そのソリューションに含まれるプロジェクトの名前を変更
   2. [.NET のソリューション](../nijo.sln) に追加
8. 空テンプレートには自動生成されたソースしか無いので、確かめたいことに必要な手書きのコードやプロジェクトを追加する

※1: .NET の整備コマンド

```sh
cd demo/999_NEW_DEMO

# 1. ファイルのリネームと、ソリューションの参照の付け替え
mv MyApp.sln Demo999.sln
mv Core.AutoGenerated/MyApp.AutoGenerated.csproj Core.AutoGenerated/Demo999.AutoGenerated.csproj
dotnet sln Demo999.sln remove Core.AutoGenerated/MyApp.AutoGenerated.csproj
dotnet sln Demo999.sln add Core.AutoGenerated/Demo999.AutoGenerated.csproj

# 2. nijo.sln に追加
cd ../..
dotnet sln nijo.sln add "demo/999_NEW_DEMO/Core.AutoGenerated/Demo999.AutoGenerated.csproj" --solution-folder "デモ999_NEW_DEMO"
```

## デモのファイルの分類

手書きのファイルは各デモで個別に管理する。デモ同士や空テンプレートとの間でファイルを共有・同期する仕組みは無い。
デモごとに必要なものが異なり、共有すると、あるデモの都合で入れた変更が他のデモに波及するため。

デモ101は、新規プロジェクト作成時に選べるデモ101テンプレートの元になる。
デモ101の手書きのファイルは、[デモ101テンプレート作成.sh](../Task/デモ101テンプレート作成.sh) でテンプレートを作るときに次のように扱われる。

| 分類   | 判定基準             | テンプレートを作るときの扱い                                                            |
| ------ | -------------------- | --------------------------------------------------------------------------------------- |
| 汎用部 | 販売管理に依存しない | デモ101テンプレートに残る                                                               |
| 業務部 | 販売管理に固有       | [Demo101TemplatePruner](../Task/Demo101TemplateBuilder/Demo101TemplatePruner.cs) で削除 |

## デモ編集時

### デモ101とデモ200の両方に当てはまる不具合を直す場合

保存処理や入力チェックなどの手書きのコードは、元は同じコードをコピーしたもので、デモ101とデモ200で個別に管理している。
同期の仕組みは無いので、片方で直した不具合がもう片方にも当てはまる場合は、手作業で両方に同じ修正を入れること。

### npmパッケージの新規追加の場合

基本的に各プロジェクトのpackage.jsonではなくモノレポのルートのpackage.jsonに追加すること。
node_modulesの容量削減のため。
